# Selected work

Three engagements that arrived as different complaints (*our dashboards
disagree*, *nobody knows how this gets approved*, *the help centre calls it
something else*) and turned out to be the same problem underneath. A concept had
more than one name, and nothing in the system was responsible for deciding which
one was right.

## How I work

I'm a technical writer and information architect for data-intensive software. I
treat a naming problem as an engineering problem rather than a style preference: a
definition two teams read differently is a defect, and it behaves like one. It
reproduces, it costs time, and it gets more expensive the longer it sits.

The sequence is consistent across the three case studies below.

1. **Map the thing before describing it.** Entities, data flows, and who owns
   which decision. For a data-intensive product the useful structure follows the
   data, not the table of contents.
2. **Fix the vocabulary.** One agreed name per concept, with the rejected
   alternatives kept so old vocabulary still leads somewhere, and with the reasoning
   recorded, because that is what stops the question being reopened.
3. **Move the mechanical work into the pipeline.** Finding every page that
   disagrees, every stale review date, every dead link. The decision stays human;
   the search does not.
4. **Make it maintainable by other people.** Metadata standards and written
   governance, so the work survives whoever set it up. Documentation only one
   person can update is a liability wearing a deliverable's clothes.

Step 3 is also what made AI useful here rather than dangerous. A pipeline that
already gates every change on the same checks does not care whether a change was
typed or drafted by an agent, which is the whole argument on
[the practice page](/practice).

## What this portfolio demonstrates

- A user-centred mindset paired with the discipline to structure complex
  information
- Experience designing and maintaining documentation systems for data-rich
  products
- Automation and AI applied where the answer already exists, and withheld where it
  has to be decided
- Ownership of cross-cutting concerns (naming, structure, metadata,
  governance) followed through to implementation
